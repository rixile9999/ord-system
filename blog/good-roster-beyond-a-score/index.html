Defining decision quality in operational AI

Feasibility, multi-objective optimization, evaluation. From definitions and counterexamples to system design and a reproducible experiment.

In this article

Decisions and requirementsWeighted sums and scalesPareto optimalityORCA engine evaluationA reproducible experimentSolver guaranteesReferences

When an AI system allocates resources or proposes a work plan, what makes its decision good? Problems involving cost, delay, and the distribution of work require an explicit definition of the decisions available and the criteria used to evaluate them.

We begin with feasibility and multi-objective optimization, examine a guarantee and a counterexample for weighted sums, explain the evaluation architecture of the ORCA engine (Operational Research Conversational Agent), the core used in RN-AI, and test the ideas by exhaustively enumerating a small resource allocation problem. The mathematical examples and experiment were created for this article.

1. Define decisions, requirements, and objectives

Let x represent an assignment or plan, and θ the inputs, including available resources, demand, and operating rules. X specifies the decision representation, while each gᵢ expresses a requirement. The feasible set is:

𝓕(θ) = {x ∈ X : gᵢ(x; θ) ≤ 0, i = 1, …, m}

Whether a candidate belongs to this set and which candidate we prefer within it are separate questions. Orienting every objective toward minimization, we can describe quality as a vector of costs:

f(x) = (f₁(x), …, fₖ(x)),   x ∈ 𝓕(θ)

For example, two objectives might be assignment cost and the spread of resource loads. A smaller spread does not capture every meaning of fairness. Different resource capabilities or contractual conditions require different comparisons. Whether a metric represents the intended operational quality is a modeling assumption that needs review.

A language model can help structure natural-language requirements and identify missing information. How those requirements become variables, constraints, and objectives still needs explicit review. If 𝓕(θ) is empty, changing objective weights alone cannot create a feasible solution.

2. Weighted sums specify trade-offs

Scalarization compares multiple objectives through a scalar value. Here we use fixed reference values aₖ and positive scales sₖ before minimizing a weighted sum:

f̃ₖ(x) = (fₖ(x) − aₖ) / sₖ,   sₖ > 0
minx ∈ 𝓕(θ) Jw(x),   Jw(x) = ∑k wₖ f̃ₖ(x),   wₖ > 0

A weight must be interpreted together with its scale. Changing a delay measurement from hours to minutes multiplies its numerical value by 60. Without adjusting the scale or weight, the objective no longer expresses the same preference. Equal weights do not mean equal importance before units and scales are specified.

Subtracting a fixed reference value does not change the ranking of candidates. Dividing by positive scales preserves dominance, but can change the weighted-sum ranking if the weights stay the same. Recomputing scales from the minimum and maximum of a changing candidate set also changes the comparison. Reproducibility therefore requires recording reference values and scales.

Strict priorities can instead motivate a lexicographic approach, which optimizes higher-priority objectives first. The choice depends on the exchanges and priorities the task permits. Gurobi’s explanation of blended and hierarchical objectives describes this distinction.

3. Pareto optimality: a guarantee and its limits

A candidate y dominates x when it is no worse on every objective and strictly better on at least one. A feasible solution is Pareto optimal if no other feasible solution dominates it.

Proposition / Positive weights

If every weight is strictly positive and a global minimum is found, a weighted-sum solution is Pareto optimal.

Proof. Suppose y dominates a global minimizer x*. Every f̃ₖ(y) ≤ f̃ₖ(x*), with at least one strict inequality. Multiplying by positive weights and summing gives Jw(y) < Jw(x*), contradicting global minimality.

This proposition does not require convexity. Its converse—that every Pareto optimal solution can be obtained with positive weights—does not hold for general discrete or nonconvex problems. Boyd and Vandenberghe’s Convex Optimization, §4.7 develops the relationship between scalarization and Pareto optimality.

Suppose the feasible candidates are exactly the following three points. Both objectives are minimized, and all three candidates are Pareto optimal.

For B’s weighted sum to be no worse than both A’s and C’s, these two conditions must hold simultaneously:

2w₁ + 3w₂ ≤ 4w₂   ⇒   w₁ / w₂ ≤ 1/2
2w₁ + 3w₂ ≤ 4w₁   ⇒   w₁ / w₂ ≥ 3/2

They cannot both hold. B is an unsupported Pareto point: no positive weighted sum selects it. This argument does not imply that points on a line joining A and C are attainable decisions. Averaging two discrete plans need not produce an executable plan.

The limitation does not apply to every scalarization method. An ε-constraint formulation minimizing f₁ subject to f₂(x) ≤ 3 selects B in this example. The formulation should reflect which alternatives need to be explored.

4. The ORCA engine separates generation and evaluation

Operational work includes modifying existing plans and reviewing plans obtained elsewhere. RN-AI is a product powered by the ORCA engine. Within the engine, the path that builds constraints and searches for solutions is separate from the path that calculates violations and penalties for a supplied result. Evaluation can run without performing another solver search.

Both paths share rule definitions and operational context. Constructing solver constraints and calculating violations in a candidate use separate execution paths. Generated and edited plans can therefore be reviewed against the same rules, with a breakdown of the contributions to their overall score.

Write evaluation conceptually as E(x; θ, R), where R is the applied ruleset. The same x can receive a different evaluation if its context or ruleset changes. A reproducible record needs the relevant inputs and rule version alongside the decision. This is a design criterion for interpreting an evaluation result.

Our checks feed generated results back through the evaluation path and compare their evaluations. This can detect discrepancies in input conversion or between execution paths. However, both paths can share an error in a rule definition. Agreement alone does not prove that the rule correctly represents the operational requirement.

Examples, counterexamples, and human-reviewed expected outcomes are needed for individual rules as well. Evaluating a supplied candidate’s violations and costs also differs from proving that the entire feasible set is empty or that no better candidate exists.

The binary variable xtr is 1 when task t is assigned to resource r. Given eligibility atr, effort dt, and capacity Cr, the constraints are:

∑r xtr = 1,   xtr ≤ atr,   xtr ∈ {0, 1}
Lr = ∑t dtxtr ≤ Cr

The first objective is total assignment cost; the second is the difference between the largest and smallest resource loads. Capacities are equal in this toy model, and a smaller load spread is an explicitly chosen objective.

fcost = ∑t,r ctrxtr,   fspread = maxr Lr − minr Lr

We exhaustively enumerated all 3⁴ = 81 assignments. There are 36 eligible combinations and 32 that also satisfy capacity constraints. They produce 26 distinct objective pairs, of which four are Pareto optimal. Multiple assignments can share an objective pair, so these counts describe different things.

The weight experiment uses fixed scales of 10 for cost and 8 for load spread. These are reference units, not min-max normalization intended to map every value into [0, 1]. The results are conditional on this choice.

Jα = α · fcost/10 + (1 − α) · fspread/8,   0 < α < 1

For example, α = 0.65 selects (8, 2). Below 5/9, the selected pair is (9, 1); above 5/7, it is (6, 6). Adjacent pairs tie at the boundaries. The Pareto optimal pair (7, 5) is never a minimizer of a positive weighted sum.

This conclusion does not rely on checking a few slider positions. For each candidate p, the reproduction code constructs Jα(p) ≤ Jα(q) for every q and intersects the resulting linear inequalities using exact Fraction arithmetic. Sampling finitely many weights is different from proving that no weight can select a point.

6. Read what the solver established

For larger problems, global optimality may remain unproven within the allotted time. In a minimization problem, let U be the objective value of the current feasible solution and L a valid lower bound. The optimal value z* satisfies:

L ≤ z* ≤ U,   absolute gap = U − L

If L = 100 and U = 120, the remaining possible objective improvement is at most 20. This bound concerns the specified model and objective; it is not a probability that the decision will succeed in practice. Relative-gap conventions and behavior near zero must be checked for the solver in use. Gurobi’s MIPGap definition specifies its denominator and special cases.

OR-Tools CP-SAT distinguishes finding a feasible solution, an optimal result, proven infeasibility, an unknown result, and an invalid model. UNKNOWN must not be read as “no solution exists.” Record the status, objective, bound, termination criteria, and configured gap tolerances. The Pareto proposition above assumes an exact global minimum.

An operational AI result should carry the decision together with its applicable conditions, objective measurements, chosen trade-offs, and established limits. ORD connects language models, optimization, and evaluation through the ORCA engine so that people can inspect this evidence and make the next decision.
