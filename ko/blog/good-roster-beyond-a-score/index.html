업무용 AI의 의사결정 품질을 정의하는 법

Feasibility, multi-objective optimization, evaluation. 정의와 반례에서 출발해, 실제 설계와 재현 가능한 실험으로 연결합니다.

이 글에서

결정·조건·목표Weighted sum과 scalePareto optimality와 반례ORD의 evaluation 구조재현 가능한 실험Solver가 확인한 범위참고 자료

업무용 AI가 자원을 배정하거나 작업 순서를 제안할 때, 그 결과를 좋다고 판단할 근거는 무엇일까요? 비용, 지연, 자원 사용의 균형처럼 여러 기준이 함께 작용하는 문제에서는 먼저 결정의 범위와 평가의 의미를 정의해야 합니다.

이 글은 feasibility와 multi-objective optimization을 출발점으로 삼습니다. Weighted sum의 보장 조건과 반례를 살펴보고, ORD의 evaluation 구조를 설명한 뒤, 작은 resource allocation 문제를 전수 열거해 논의를 검증합니다. 수식과 실험은 이 글을 위한 공개 예제입니다.

1. 결정, 조건, 목표를 먼저 정의합니다

결정할 배정이나 계획을 x, 가용 자원·수요·운영 규칙 같은 입력을 θ라고 하겠습니다. X는 결정의 표현 방식이고, gᵢ는 반드시 만족해야 하는 조건입니다. Feasible set은 다음과 같습니다.

𝓕(θ) = {x ∈ X : gᵢ(x; θ) ≤ 0, i = 1, …, m}

어떤 후보가 이 집합에 속하는지와, 그 집합 안에서 어떤 후보를 선호하는지는 별개의 질문입니다. 모든 objective를 최소화하는 방향으로 맞추면, 후보의 품질을 비용들의 vector로 표현할 수 있습니다.

f(x) = (f₁(x), …, fₖ(x)),   x ∈ 𝓕(θ)

예를 들어 배정 비용과 자원별 부하의 편차를 두 objective로 둘 수 있습니다. 편차가 낮다는 사실을 공정성 전체와 동일시하지는 않습니다. 자원별 처리 능력이나 계약 조건이 다르면 비교 기준도 달라집니다. 어떤 측정값이 업무에서 원하는 품질을 대변하는지는 model 밖에서 검토해야 하는 가정입니다.

Language model은 자연어 요구를 정리하고 누락된 조건을 확인하는 데 활용할 수 있습니다. 그 요구를 어떤 variable, constraint, objective로 표현할지는 명시적으로 검토해야 합니다. 𝓕(θ)가 비어 있다면 objective의 weight를 바꾸는 것만으로 feasible solution이 생기지는 않습니다.

2. Weighted sum은 trade-off를 정하는 방법입니다

여러 objective를 하나의 값으로 비교하는 방법을 scalarization이라고 합니다. 여기서는 고정한 기준값 aₖ와 positive scale sₖ를 사용해 단위를 정리하고 weighted sum을 최소화합니다.

f̃ₖ(x) = (fₖ(x) − aₖ) / sₖ,   sₖ > 0
minx ∈ 𝓕(θ) Jw(x),   Jw(x) = ∑k wₖ f̃ₖ(x),   wₖ > 0

Weight는 scale과 함께 해석해야 합니다. 예를 들어 지연을 시간에서 분으로 바꾸면 숫자가 60배가 됩니다. Scale이나 weight를 조정하지 않으면 같은 선호를 표현하는 objective가 아닙니다. Equal weights도 단위와 scale이 정해지기 전에는 동등한 중요도를 뜻하지 않습니다.

고정한 기준값을 빼는 연산은 후보 간 순위를 바꾸지 않습니다. Positive scale로 나누면 dominance 관계는 보존되지만, 같은 weight를 그대로 사용할 때 weighted sum의 순위는 달라질 수 있습니다. 후보가 바뀔 때마다 min/max로 scale을 다시 정하면 비교 기준도 움직이므로, 재현 가능한 비교에는 기준값과 scale을 함께 기록해야 합니다.

엄격한 우선순위가 있는 경우에는 상위 objective를 먼저 최적화하는 lexicographic approach도 고려할 수 있습니다. 목표 사이에 허용할 교환과 우선순위를 명확히 정하는 것이 선택의 기준입니다. Gurobi 문서의 blended·hierarchical objectives 설명은 이 차이를 정리합니다.

3. Pareto optimality: 보장과 역방향의 한계

후보 y가 모든 objective에서 x보다 나쁘지 않고, 적어도 하나에서 더 좋으면 y가 x를 dominate한다고 합니다. Feasible set 안에 자신을 dominate하는 후보가 없는 해가 Pareto optimal입니다.

Proposition / Positive weights

모든 weight가 strictly positive이고 global minimum을 찾았다면, weighted sum의 해는 Pareto optimal입니다.

Proof. 최적해 x*를 dominate하는 y가 있다고 가정합니다. 모든 f̃ₖ(y) ≤ f̃ₖ(x*)이고 하나 이상은 strict inequality입니다. Positive weights를 곱해 더하면 Jw(y) < Jw(x*)가 되므로 global minimum이라는 가정과 모순입니다.

이 명제에는 convexity가 필요하지 않습니다. 반면 모든 Pareto optimal solution을 positive weighted sum으로 찾을 수 있다는 역방향은 일반적인 discrete·nonconvex 문제에서 성립하지 않습니다. Scalarization과 Pareto optimality의 관계는 Boyd와 Vandenberghe의 Convex Optimization, §4.7에서 다룹니다.

가능한 후보가 아래 세 개뿐이라고 가정해 보겠습니다. 두 objective 모두 작을수록 좋고, 세 후보는 모두 Pareto optimal입니다.

B가 A와 C보다 weighted sum에서 나쁘지 않으려면 다음 두 조건을 동시에 만족해야 합니다.

2w₁ + 3w₂ ≤ 4w₂   ⇒   w₁ / w₂ ≤ 1/2
2w₁ + 3w₂ ≤ 4w₁   ⇒   w₁ / w₂ ≥ 3/2

두 조건은 양립할 수 없습니다. B는 Pareto optimal이지만 positive weighted sum으로는 선택되지 않는 unsupported point입니다. 여기서 A와 C 사이를 잇는 선 위의 점이 실제 가능한 결정이라는 뜻은 아닙니다. Discrete 문제에서 두 계획을 평균한 것이 실행 가능한 계획이 된다고 가정할 수는 없습니다.

이 한계는 모든 scalarization에 대한 불가능성을 뜻하지 않습니다. 예를 들어 f₂(x) ≤ 3이라는 조건 아래 f₁을 최소화하는 ε-constraint 방식은 위 예제에서 B를 선택합니다. 어떤 대안을 탐색해야 하는지에 따라 formulation을 선택해야 합니다.

4. ORD는 생성과 evaluation을 분리합니다

실제 업무에서는 이미 만들어진 계획을 수정하거나, 다른 경로에서 가져온 계획을 검토하는 일이 생깁니다. ORD의 RN-AI에서는 constraints를 구성해 해를 탐색하는 경로와, 주어진 결과의 위반 및 항목별 penalty를 계산하는 경로를 나눴습니다. Evaluation은 solver 탐색을 다시 실행하지 않고 사용할 수 있습니다.

두 경로는 rule definitions와 운영 context를 공유합니다. Solver용 constraints를 구성하는 코드와 결과에서 위반을 계산하는 코드는 서로 다른 실행 경로입니다. 이 구조 덕분에 생성된 계획과 편집한 계획을 같은 규칙으로 검토할 수 있고, 전체 점수뿐 아니라 어떤 항목이 결과에 기여했는지도 확인할 수 있습니다.

Evaluation을 개념적으로 E(x; θ, R)라고 쓰면, R은 적용한 ruleset입니다. 같은 x라도 context나 ruleset이 바뀌면 평가가 달라질 수 있습니다. 재현 가능한 결과 기록에는 결정뿐 아니라 해당 입력과 규칙의 version도 필요합니다. 이는 evaluation 결과를 해석하기 위한 설계 기준입니다.

실제 검증에서는 생성한 결과를 evaluation 경로에 다시 입력해 평가가 일치하는지 확인합니다. 이 비교는 입력 변환이나 서로 다른 실행 경로의 불일치를 찾는 데 유용합니다. 다만 같은 rule definition의 오류를 두 경로가 공유할 수 있으므로, 결과가 일치한다는 사실만으로 업무 요구를 올바르게 표현했다는 증명이 되지는 않습니다.

개별 rule에 대한 예제·반례와 사람이 검토한 기대 결과가 함께 필요합니다. 또 evaluation은 주어진 후보의 규칙 위반과 비용을 평가합니다. Feasible set 전체가 비어 있는지, 더 좋은 후보가 존재하지 않는지를 증명하는 작업은 별도로 다뤄야 합니다.

작업 네 개를 자원 세 개에 하나씩 배정합니다. 각 작업은 나눌 수 없고, 모든 작업을 정확히 한 자원에 배정합니다. 작업량은 [2, 2, 3, 1], 자원별 capacity는 [6, 6, 6]입니다. 아래 숫자는 배정 비용이며 ‘불가’는 허용되지 않는 배정입니다. 모두 설명을 위해 만든 값입니다.

Binary variable xtr는 작업 t를 자원 r에 배정하면 1입니다. 허용 여부 atr, 작업량 dt, capacity Cr를 사용하면 조건은 다음과 같습니다.

∑r xtr = 1,   xtr ≤ atr,   xtr ∈ {0, 1}
Lr = ∑t dtxtr ≤ Cr

첫 objective는 총 배정 비용, 둘째는 최대 부하와 최소 부하의 차이입니다. 이 toy model에서 자원의 capacity는 같으며, 부하 차이를 작게 만드는 것을 하나의 명시적 목표로 선택했습니다.

fcost = ∑t,r ctrxtr,   fspread = maxr Lr − minr Lr

3⁴ = 81개 배정을 실제로 전수 열거했습니다. 허용된 배정 조합은 36개이고, capacity까지 만족하는 배정은 32개입니다. 서로 다른 objective pair는 26개, Pareto optimal pair는 네 개였습니다. 한 pair에 여러 배정이 대응할 수 있으므로 계획의 개수와 objective pair의 개수는 구분합니다.

Weight 실험에는 고정 scale 10과 8을 사용했습니다. 각각 비용과 부하의 기준 단위이며, 모든 값을 반드시 [0, 1]로 만드는 min-max normalization은 아닙니다. 이 선택에 대한 결과임을 명시합니다.

이 결론은 slider의 일부 값만 검사해서 내리지 않았습니다. 재현 코드는 각 후보 p에 대해 모든 q와의 Jα(p) ≤ Jα(q)를 구성하고, 선형 부등식을 만족하는 α 구간의 교집합을 Fraction으로 정확하게 계산합니다. 유한한 weight sampling과 ‘어떤 weight에서도 선택되지 않는다’는 증명은 구분해야 합니다.

6. Solver가 확인한 범위를 읽습니다

큰 문제에서는 정해진 시간 안에 global optimality를 증명하지 못할 수 있습니다. Minimization에서 현재 feasible solution의 objective value를 U, 유효한 lower bound를 L이라고 하면 최적값 z*는 다음 범위에 있습니다.

L ≤ z* ≤ U,   absolute gap = U − L

L = 100, U = 120이면 현재 계획에서 개선 가능한 objective value는 최대 20입니다. 이 bound는 해당 model과 objective에 대한 수학적 범위이며, 결과가 현실에서 성공할 확률을 뜻하지 않습니다. Relative gap은 solver의 정의와 0 근처 처리 방식을 확인해야 합니다. Gurobi의 MIPGap 정의도 분모와 특수한 경우를 명시합니다.

OR-Tools CP-SAT은 feasible solution을 찾은 상태, optimal 결과, infeasibility의 증명, 판정하지 못한 상태, invalid model을 구분합니다. UNKNOWN을 ‘해가 없음’으로 읽으면 안 됩니다. 결과를 기록할 때는 status, objective, bound, 종료 조건과 설정한 gap tolerance를 함께 확인해야 합니다. 앞서의 Pareto 명제는 정확한 global minimum을 가정합니다.

업무용 AI의 결과에는 실행할 결정과 함께, 적용한 조건, objective별 측정값, 선택한 trade-off, 확인한 범위가 담겨야 합니다. ORD는 이 정보를 검토하고 다음 결정을 내릴 수 있도록 language model, optimization, evaluation을 연결합니다.
