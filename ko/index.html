02 / 04 — 운영 문제model 구성 보기

language model + 문제 정의

요청에 담긴 조건을
명확하게 정의합니다.

운영 요청에는 조건이 생략되거나 모호하게 표현될 수 있습니다. agent는 language model로 요청을 구조화하고, 빠진 정보를 질문하며, 불분명한 조건을 확인한 뒤 계산합니다.

  1. 01요청에서 가용 자원, 필요한 업무, 우선순위를 파악합니다.
  2. 02반드시 지켜야 할 조건과 조정할 수 있는 목표를 확인합니다.
  3. 03확인된 조건을 decision variables, constraints, objective로 표현합니다.
앞의 배정 문제를 model로 표현요청 → Model
요청 예시
“오늘 오전 방문 업무 세 건을 모두 배정하고, 이동 시간은 줄여주세요.”
계산 전 확인

이 시간대에 한 팀이 두 건 이상 맡아도 되나요?

확인된 조건: 아니요. 팀당 한 건만 맡을 수 있습니다.

Decision variables
assign[team, visit] ∈ {0, 1}
각 방문 업무를 맡을 팀을 선택합니다.
Hard constraints
  • 각 방문 업무에 정확히 한 팀을 배정합니다.
  • 각 팀은 최대 한 건만 맡습니다.
  • 사용 가능한 팀만 배정합니다.
Objective
min Σ travel[team, visit] × assign[team, visit]

반드시 지켜야 할 조건과 solver가 개선할 목표를 model에 명시합니다.

solver는 배정과 objective 값을 반환합니다. agent는 model의 조건에 맞는 결과인지 확인하고 검토를 요청합니다. 승인된 작업은 연결된 tool을 통해 실행합니다.

가용 자원 변경 → model 수정 → 재계산조건이 서로 충돌하면 확인을 요청합니다.
